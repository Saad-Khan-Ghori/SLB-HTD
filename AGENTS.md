# Repository Guidelines

Last reviewed: 2026-11-17. Review after major project changes.

## Project Structure & Module Organization

This Python/Bash project keeps the proxy in `slb.py` and test servers in `backend.py`. `setup_topology.bash` creates seven Linux network namespaces; `run_poc_demo.bash` and `run_experiments.bash` drive the demo and benchmark. `test_local_loopback.py` is the functional test. `analyze_results.py` summarizes measured logs, and `build_measured_report.py` regenerates the report. `simulator/` contains a browser teaching model. Earlier modelled data are archived in `modelled/`.

## Build, Test, and Development Commands

Use Python 3.10+ on Linux. There is no build step or dependency manifest. The proxy, backend, tests, and measured analyzer use the standard library. Illustrative diagrams need Matplotlib. Namespace workflows also need `iproute2`, `curl`, `hey`, and HAProxy; live capture uses `tcpdump`.

- `python3 slb.py --help` and `python3 backend.py --help`: inspect local run options.
- `python3 test_local_loopback.py`: exercise round robin, least connections, IP hash, failover, and recovery without root.
- `python3 -m unittest -v test_analyze_results.py`: check measured-log parsing and the trial manifest.
- `python3 simulator/serve.py`: serve the illustrative visual simulator on localhost.
- `node simulator/test_engine.mjs`: verify the simulator scheduling and health-state model.
- `sudo bash setup_topology.bash setup` followed by `sudo bash setup_topology.bash verify`: create and inspect the routed topology.
- `sudo bash run_poc_demo.bash`: run the live demonstration and capture traffic where `tcpdump` is available.
- `sudo bash run_experiments.bash`: run the full benchmark, retain logs under `experiments/raw_runs/`, and summarize measured trials.
- `sudo bash setup_topology.bash teardown`: remove namespaces and their processes after testing.

## Coding Style & Naming Conventions

Follow the existing four-space Python indentation, type hints, `snake_case` functions and variables, and `PascalCase` classes. Bash scripts use `set -euo pipefail`, quoted expansions, and uppercase configuration variables. Keep command-line policy names (`rr`, `lc`, `iphash`) and backend names (`B1`–`B3`) consistent. No formatter or linter is configured; review formatting manually.

## Testing Guidelines

The functional suite is a standalone assertion-based script, not a pytest suite; no coverage target is defined. Extend `test_local_loopback.py` for behavior changes, especially scheduling and health transitions. Check Bash syntax with `bash -n *.bash`. Namespace tests require root and should end with teardown. Keep raw trial logs with any measured CSVs.

## Commit & Pull Request Guidelines

This checkout has no Git history, so no established commit convention can be verified. Use a short imperative subject, such as `Fix loopback test paths`. In pull requests, describe the behavior changed, commands run, and any generated CSV, log, or capture changes; link the relevant issue and include figures or screenshots when visual output changes.

## Scope, architecture, and directory conventions

This is a local teaching/research prototype, not a production service. Preserve split TCP termination, one request per connection, active-only health transitions, and the distinction between live measurements and the independent browser simulator. Policies are selected at process startup. Keep source, tests, and Bash entry points at the root unless all dependent paths are updated together. Supporting documents belong in `docs/`; start with [README](README.md), [context](PROJECT_CONTEXT.md), and [architecture](docs/ARCHITECTURE.md).

## Generated artifacts and evidence safety

- Preserve `experiments/raw_runs/` and `modelled/` as evidence/history. Archive the baseline before running experiments: matching trial logs are deleted and CSVs overwritten.
- Regenerate `experiments/*.csv` with `analyze_results.py`, `MEASURED_RESULTS.md` with `build_measured_report.py`, and `output/pdf/` with `render_measured_pdf.py`. Do not manually change numerical outputs. The report builder has baseline-specific prose and dates; update the generator and verify claims for new data.
- Change HAProxy config generation in `setup_topology.bash`; setup overwrites `configs/haproxy_*.cfg`.
- `captures/` holds live captures; `illustrative/` holds constructed examples generated by `generate_pcapng_and_diagrams.py`. Never present illustrative packets as measured evidence.
- Python caches are disposable and ignored. Preserve raw logs with reports, and avoid committing local environments or secrets.

## Additional tooling and validation

There is no install/build step, configured linter, or type checker for the core. PDF regeneration requires ReportLab; illustrative generation requires Matplotlib. Routing verification requires `ping` and either `traceroute` or `tracepath`; `ethtool` is optional. Node.js runs simulator checks. No environment variable setup or database is required.

Run checks proportional to the change: loopback tests for proxy/backend behavior, analyzer unit tests for parsing, simulator engine checks for model changes, and `bash -n` on each modified Bash script. Check documentation links and commands after moving files. Root namespace workflows mutate the host network lab, remove matching namespaces, and regenerate configs. Use a dedicated lab and teardown after failures as well as success; do not run them merely to check documentation. No credentials or private data belong in documentation or logs.

## Documentation maintenance

Update `README.md`, `PROJECT_CONTEXT.md`, and `docs/ARCHITECTURE.md` when behavior, configuration, dependencies, or entry points change. Maintain `AGENTS.md` when contributor rules change and record notable changes in `CHANGELOG.md`. Keep review dates current. Describe unresolved facts as **Needs verification**. Preserve existing human-authored guidance and historical evidence.

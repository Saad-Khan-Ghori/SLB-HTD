# Implemented architecture

Last reviewed: 2026-11-17. Review after major project changes.

## System boundary and components

SLB-HTD is a local HTTP teaching lab. Core source and test entry points remain at the repository root because scripts and tests resolve them there. The browser simulator is an independent static application, not a controller for the live proxy.

```text
ns-client → ns-r1 → ns-r2 → ns-lb:8080 → br-be → ns-b1:8001
                                              → ns-b2:8002
                                              → ns-b3:8003
```

| Network | Addresses and behavior |
| --- | --- |
| Client `192.168.10.0/24` | Client `.50`, `.51`, `.52`; R1 `.1` |
| Transit `10.0.0.0/30` | R1 `.1`, R2 `.2`; netem loss on both transit egress interfaces |
| DMZ `192.168.20.0/24` | R2 `.1`, proxy `.10:8080` |
| Backend `172.20.0.0/24` | Proxy bridge `.10`; B1 `.11:8001`, B2 `.12:8002`, B3 `.13:8003` |

`setup_topology.bash` enables forwarding on R1/R2 only. Backends have no default route. Isolation is achieved by the configured routes and forwarding state; no authentication or TLS is implemented.

## Request and background flows

`SoftwareLoadBalancer.handle_client` reads through the HTTP header terminator, rewrites `Connection: close`, chooses an UP backend, increments its active count before connecting, and streams bytes until backend EOF. It decrements the count and closes sockets on completion. Requests carry one transaction per TCP connection. Request bodies are not forwarded and unsupported methods are not explicitly rejected by the proxy.

`select_backend` cycles the current healthy list for `rr`, minimizes active counts then configured order for `lc`, and computes seeded CRC32(client IP) modulo healthy count for `iphash`. Hash mappings may change when the pool changes. Policy is selected at process startup; the demo restarts the proxy between policies.

`health_check_loop` probes backends concurrently using `GET /health`. Defaults are a one-second interval, a 0.5-second timeout per connect/write/status-read operation, fall=3, rise=2. Backends start UP. Failed client requests do not themselves change health state. During detection, a dead backend may still be selected and return 502; there is no retry. No healthy backend also yields 502. Probe duration can exceed 0.5 seconds in total.

## HTTP interfaces

| Surface | Implemented behavior |
| --- | --- |
| Proxy `192.168.20.10:8080` by default | Forwards request headers to selected backend; intended for GET traffic |
| Backend `GET /health` | Immediate HTTP 200, excluded from application request counts |
| Backend other GET paths | HTTP 200 diagnostic body after configured delay; query preserved in body |
| Simulator `127.0.0.1:8765` | `simulator/serve.py` serves files from `simulator/` |

`--allow-sim-ip-header` allows `X-Sim-Client-IP` to override affinity identity for local tests. Leave it disabled in real traffic. There is no management API or persistent state store.

## Experiment and reporting flow

`run_experiments.bash` creates the topology and starts delayed backends (0/50/150 ms), then SLB or HAProxy, and `hey`. E1 has 6 policy trials; E2 has 18 loss trials; E3 has 18 failure/recovery trials; E4 has 18 concurrency trials. E3 lasts 60 seconds, stopping B2 near 30 seconds and restarting near 45; other trials last 30 seconds. Cleanup runs on script exit.

Raw `hey`, proxy and backend logs, E3 event timestamps and restart PID records go in `experiments/raw_runs/`. `analyze_results.py` validates expected client tags, parses status/connection errors and backend counts, derives recovery from B2's first request after restart, and writes per-run and summary CSVs. Missing health timestamps remain blank. `--allow-partial` permits an incomplete expected tag set; it does not manufacture measurements.

`build_measured_report.py` reads the per-run CSV and raw logs and writes `MEASURED_RESULTS.md`; it checks row count and referenced files but also embeds baseline-specific narrative. `render_measured_pdf.py` reads that Markdown and writes `output/pdf/SLB_HTD_Measured_Results.pdf` using ReportLab. Review dates and interpretation when regenerating for a new run.

## Configuration, operations, and recovery

There is no build pipeline, database migration, cloud deployment, or configured CI. Core tools use the standard library and CLI options. The simulator uses browser ES modules with no bundle step. Run and test commands are in [README](../README.md).

Proxy events include timestamps/epochs, health transitions and failures; `--verbose` adds per-request access logs. Backends log health and application requests separately. HAProxy baseline warning lines lack usable detection timestamps. Namespace setup regenerates configs and tears down matching namespaces first. The demo overwrites its logs/captures and does not install an exit cleanup trap; run explicit teardown after success or failure. The experiment runner deletes matching trial files. Back up `experiments/` before rerunning, retain source/configuration with each baseline, and restore saved evidence as a coherent set. No automated backup/restore facility exists.

## Constraints and remaining risks

The measured baseline has a client source-port bottleneck. Partial backend-response failure can append an invalid second HTTP status line. Request-body handling and total health deadlines need improvement. There is no pooling, persistent connection support, TLS, authentication, or retry. The simulator's loss chance cannot model TCP retransmission. See [improvement priorities](PROXY_IMPROVEMENTS.md) and [modelled-data caveats](MODELLED_RESULTS.md). Production deployment status and benchmark host/kernel/tool versions are **Needs verification**; they are not established by source code or the retained report.
